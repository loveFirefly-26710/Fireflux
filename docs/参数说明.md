# Fireflux 参数说明

这份文档讲的是**客户端自己**能调的参数：改哪个文件里的哪个值，`pnpm build`（或 `pnpm dist`）之后软件会变成什么样。
每条都给出「位置 → 现值 → 改了之后是什么样」。

分成四块：

- **一、打包身份** —— 影响安装包、快捷方式、Release 的版本号
- **二、界面骨架与布局** —— 窗口多大、侧栏有哪些页面、面板能拖多宽
- **三、看板娘** —— 模型大小位置、按钮带子、跟随手感
- **四、性能与省电** —— 软件渲染下的关键参数

后面还有 **五、内容与资源规则**、**六、不用重编译就能改的（运行时设置）**、**七、改完怎么验证**，
以及 **八、动态页加载失败时的排查与相关参数**（内嵌 Memos 的图片裂开、连接被拒先看这一节）。

> 想改的是**博客主题**的参数（站点标题、壁纸、评论系统那些）？那不用改代码 —— 在客户端的「配置中心」里改即可。

## 一、打包身份（`package.json` 的 `build` 段）

| 参数 | 现值 | 改了之后是什么样 |
|---|---|---|
| `productName` | `Fireflux` | 桌面/开始菜单快捷方式的名字、控制面板里卸载项的名字、`release\win-unpacked\` 里的 **exe 文件名**（现为 `Fireflux.exe`） |
| `name` | `fireflux` | npm 包名；**同时决定默认安装目录** `%LOCALAPPDATA%\Programs\<name>`（productName 含中文时会回退成它，所以保持 ASCII 最稳） |
| `version` | `0.1.0`（源码基线） | 本地 `pnpm dist` 使用该值；GitHub Actions 发布时会在云端临时改成十进制进位版本：运行号 1~9 生成 `0.1.1`~`0.1.9`，运行号 10 进位为 `0.2.0`；推送 `vX.Y.Z` 标签时使用标签版本，每段限制为 `0~9` |
| `appId` | `com.fireflux.app` | NSIS 安装器的 GUID 与卸载注册表键：**改了等于换一个安装身份**，老版本认不出新版本，会并排装成两个应用 |
| `nsis.artifactName` | `fireflux-${version}-setup.${ext}` | 安装包文件名（Release 里下载到的就是它） |
| `nsis.oneClick` | `false` | 改成 `true` 就是双击即装的静默安装，没有向导页 |
| `nsis.allowToChangeInstallationDirectory` | `true` | 改成 `false` 就不让用户自选安装目录 |
| `win.icon` | `build/icon.png` | exe、快捷方式与安装包的图标（换一张正方形 png 即可，构建时自动转 ico） |
| `directories.output` | `release` | 打包产物目录；`.gitignore` 里已忽略 |
| （未配代码签名） | — | 用户首次运行安装包会看到 SmartScreen 提示。想消除需要买代码签名证书，并在 `win` 段加 `certificateFile` / `certificatePassword` |

## 二、界面骨架与布局

### 窗口本身（`src/main/index.ts`）

| 参数 | 现值 | 改了之后是什么样 |
|---|---|---|
| `width` / `height` | 1400 / 1050 | 首次启动时窗口多大（用户拖过的大小由 Windows 记忆） |
| `minWidth` / `minHeight` | 1000 / 660 | 窗口能被拖到多小；注意**高度小于 700 时看板娘按设计自动隐藏**（阈值在 `App.svelte` 里） |
| `title` | `Fireflux` | 窗口标题栏文字（另一处来源是 `src/renderer/index.html` 的 `<title>`，改标题两处都要改） |
| `backgroundColor` | `#f5f6f8` | 界面还没画出来时的窗口底色（避免启动瞬间白闪） |
| `F12` 快捷键 | 打开 DevTools | 删掉 `before-input-event` 那段，用户就按不出调试面板 |

### 侧栏导航（`src/renderer/src/App.svelte` 的 `nav` 数组）

| 参数 | 现值 | 改了之后是什么样 |
|---|---|---|
| `nav` 数组 | 7 项：动态发布 / 文章管理 / 项目展示 / Spec 页面 / 配置中心 / 发布上线 / 设置 | 侧栏里出现的入口。删掉一项，编译后侧栏就少一个页面（页面组件还在，只是进不去）；改 `icon` 换 emoji，改 `label` 换文字 |
| `window.innerHeight >= 700` | 700 | 窗口高度阈值：低于它自动隐藏看板娘（窄窗口下省 CPU） |
| 品牌位 `✨ Fireflux` | 侧栏与引导页各一处 | 界面左上角显示的字 |

### 面板宽度（可拖拽分隔条的取值范围与记忆值）

| 位置 | 参数 | 现值 | 改了之后是什么样 |
|---|---|---|---|
| 侧栏（`App.svelte`） | `DragBar` 的 `min` / `max` | 190 / 460 | 侧栏能被拖多窄/多宽；**侧栏越宽，看板娘容器上限越大**（容器宽 = 模型大小 × (侧栏宽 − 26)） |
| 侧栏宽度默认值 | `localStorage['ff.sidebar-w']` | 216 | 用户没拖过时侧栏多宽；清掉这个键就回到默认值 |
| 列表/编辑器（`ContentManager.svelte`） | `min` / `max` | 320 / 860 | 编辑区能被拖多窄/多宽 |
| 编辑器宽度默认值 | `localStorage['ff.editor-w']` | 560 | 同上 |
| 配置中心列表（`ConfigCenter.svelte`） | `min` / `max` | 220 / 460 | 配置清单那一列能被拖多宽 |
| 配置中心宽度默认值 | `localStorage['ff.cc-w']` | 280 | 同上 |
| 手柄居中补偿 | `gapLeft={14}`（App 传） | 14 | 侧栏那条拖拽条的手柄位置：改错了手柄就会偏左/偏右，不落在两块面板的分界线上 |

## 三、看板娘

> **成对参数警告**：`MENU_BAND`（`App.svelte`，容器右侧按钮带宽度）与 `controlsGutter`（`embed.html`，iframe 里给按钮留的带子）**必须是同一个数**。只改一处，按钮就会压到模型上，或与模型之间空出一截。

| 参数 | 位置 | 现值 | 改了之后是什么样 |
|---|---|---|---|
| `MENU_BAND` / `controlsGutter` | `App.svelte` / `embed.html` | 40 | 容器右侧留给 🔙😊🔗❌ 那列按钮的宽度。调大＝模型那一列变窄、按钮更宽松；调小＝模型更宽 |
| 容器宽度 | `App.svelte` 的 `live2dSlotW` | `clamp(模型大小, 0.3~1) × (侧栏宽 − 26)` | 看板娘容器多宽。那个 26 = 侧栏左右各 12px 内边距 + 各 1px 边框，改侧栏内边距要一起改 |
| 容器高度 | `App.svelte` 的 `live2dSlotH` | `模型列宽 ÷ 宽高比 + 2` | 末尾的 +2 是取整余量，去掉它模型顶边可能被裁 1px |
| 模型基准摆放 | `embed.html` 的 `scale` / `offsetX` / `offsetY` | 0.94 / −20 / 12 | 模型在画布里的原始缩放与偏移（上游 Firefly-live2d-6.6.2 官方值）。一般用界面上的「调整看板娘」就够了，不必动这里 |
| 触摸端那一组 | `embed.html` 的 `touchWidth` / `touchHeight` / `touchScale` / `touchOffsetX` / `touchOffsetY` | 260 / 220 / 0.9 / −12 / 8 | 触摸设备上的尺寸与摆放（桌面端用不到） |
| CPU 帧率上限 | `embed.html` 的 `maxFPS` / `frame-pacer.js` | 60 | CPU 软件渲染最多每秒 60 帧，并与显示刷新同步；慢帧会丢弃错过的显示时间点。GPU 模式不使用这个人工上限，直接接受每个显示刷新回调 |
| 指针转发节拍 | `App.svelte` 的 `onPointerTrack()` | CPU 60 帧上限 / GPU 每个事件 | CPU 路径合并高频指针事件并按 60 帧上限转发；GPU 路径立即转发，不增加人工帧率门控 |
| 抗锯齿 | `embed.html` 的 `antialias` | `false` | 软件渲染下 MSAA 每帧都是纯 CPU 开销：打开画面更干净但更卡 |
| 渲染分辨率 | `embed.html` 的 `resolution` / `setRenderMode()` | CPU 0.8 / GPU DPR | CPU 模式默认 0.8x，减少软件光栅化的像素量；GPU 模式按设备像素比（最高 2x）渲染。URL 显式传 `res` 时覆盖自动值 |
| 物理仿真 | `embed.html` 的 `physics` | 1 | 头发/衣摆飘动，是 CPU 大头；填 0 完全静止 |
| 欢迎语与闲置说话 | `embed.html` 的 `welcome` / `idleMessageDelay` / `idleMessageInterval` | `开拓者，我回来啦~` / 150000 / 180000 | 加载后说的第一句话、多久不搭理她开始说话、之后隔多久再说一次 |
| 消息框与头顶的距离 | `firefly-loader.js` 的 `dialogGap` | 24 | 消息框离模型头顶多远（另有 6px 基础安全距离） |
| 按钮大小规则 | `firefly-loader.js` 的 `positionControls()` | 12~34px，按容器高度算 | 容器变矮时按钮自动缩小，保证 4 个按钮不超出容器 |
| 流畅动画保持时长 | `App.svelte` 的 `LIVE_GRACE_MS` | 8000ms | 指针停在侧栏（正看着她）时保持流畅动画多久。另外几处：窗口别处移动时 1500ms、与看板娘互动后 12000ms、iframe 刚加载后 6000ms |
| 调整后落盘防抖 | `App.svelte` 的 `changeLive2d` | 600ms | 拖完/滚轮停下多久才写入设置（防止一次拖拽狂写文件） |
| 设置页滑块范围 | `Settings.svelte` | 模型大小 0.3~1（步进 0.02）、水平 ±150px、垂直 −160~80px | 界面上能调的区间；改小了用户就拖不到那个范围 |
| 主题色板 | `Settings.svelte` 的 `ACCENTS` | 5 套：流萤·薄荷 #14B8A6、琥珀·余烬 #F59E0B、樱粉·梦境 #EC7FA9、星穹·蓝 #5B8DEF、极光·紫 #8B7CF6 | 设置页里那排色块。**改色名或改默认色要三处同改**：这里的 `name`、同文件里 `a.name === '流萤·薄荷'` 的默认高亮判断、以及 `app.css` 的 `--accent: #14b8a6` |

## 四、性能与省电

| 参数 | 位置 | 现值 | 改了之后是什么样 |
|---|---|---|---|
| 背景渐变三色 | `src/renderer/src/lib/bg-bake.ts` 的 `GRADIENT.stops` | `#eafaf6` → `#f4fbf8` → `#fdf8ef`（155°） | 客户端底部那层渐变背景的配色（`app.css` 里也有一份同样的，两处要一致） |
| 烘焙图质量 | `bg-bake.ts` 的 `toBlob(..., 'image/webp', 0.92)` | WebP 0.92 | 背景预烘焙位图的格式与质量；调低更省内存，它只是一层背景，调高没必要 |
| 重烘焙防抖 | `App.svelte` 的 `bakeTimer` | 600ms | 窗口尺寸变化后多久重新烘焙背景（避免拖窗口时反复编码） |
| 布局冻结时长 | `App.svelte` 的 `freezeTimer` | 180ms | 窗口缩放时把布局钉住多久（否则侧栏宽度每变一次就重建一次 WebGL 画布） |
| 拖拽/缩放/失焦暂停 | `App.svelte` 的 `pausedByDrag` / `pausedByResize` / `pausedByFocus` | 三条都启用 | 让看板娘在拖分隔条、缩放窗口、窗口失焦时完全不渲染；去掉任何一条都会在那段时间多烧 CPU |
| 默认渲染参数 | `src/main/index.ts` | `in-process-gpu` + `use-angle swiftshader` + `enable-unsafe-swiftshader` | 让 GPU 进程内运行并强制 SwiftShader（兼容显卡驱动异常的机器）。用户可在设置页开「硬件加速渲染」，此时不追加这三个参数（需重启生效） |
| 防崩溃参数 | `src/main/index.ts` | `no-sandbox`、`disable-features NetworkServiceSandbox,RendererCodeIntegrity`、`network-service-in-process` | 关掉沙箱与渲染器完整性校验（第三方 DLL 注入环境下子进程易崩）。普通机器想更安全可以去掉，但要去掉后实测不崩 |
| 开发用环境变量 | `src/main/index.ts` | `FF_REMOTE_DEBUG`（远程调试端口）、`FF_FORCE_DSF`（强制 1 倍像素）、`FF_DRAG_BENCH`（归因台） | 只在开发时派用场，不设置就完全无效 |

## 六、不用重编译就能改的（运行时设置）

这些在设置页点一点就生效，落盘在 `data/settings.json`，**不需要重新编译**：

| 项 | 效果 |
|---|---|
| 主题色（5 套色板） | 客户端全局强调色（按钮、进度条、选中态） |
| 软件壁纸 + 壁纸减淡 | 客户端背景图与它的淡化程度 |
| 卡片 / 侧栏不透明度 | 面板半透明程度，调低能露出后面的壁纸 |
| 看板娘开关 | 关掉后侧栏更清爽，拖拽也更流畅 |
| 模型大小 / 水平位置 / 垂直位置 | 等同于代码里的容器公式与位移；也可用侧栏的「调整看板娘」直接拖 |
| 数据目录 | 设置、壁纸、网页会话存到哪里（切换前会先复制过去） |
| 硬件加速渲染 | 允许 GPU 独立进程参与渲染，点击后自动重启生效 |
| 博客项目文件夹 | 客户端管理的目标项目，可随时更换绑定 |
| 面板宽度 | 直接拖分隔条，宽度记在 localStorage（`ff.sidebar-w`、`ff.editor-w`、`ff.cc-w`） |

## 七、改完怎么验证

```bash
pnpm typecheck                                          # 类型检查
pnpm build && FF_SMOKE=1 node scripts/bench-drag.mjs     # 逐页冒烟：7 个页面有没有运行时报错
FF_INTERACT_TEST=1 node scripts/bench-drag.mjs           # 改看板娘必跑：视线收敛、命中、冻结 + 区域截图
pnpm dist                                                # 改打包身份必跑：确认 release/ 里的文件名对不对
```

`pnpm build` 的输出应当**没有任何 Svelte 警告**（历史上那两条 a11y / `state_referenced_locally` 已修，见开发笔记）；如果冒出新警告，就是这次改动带进来的。

想验证网页诊断这条链路（不用真的等服务器坏）：打开动态发布页，按 F12 在控制台执行一次注定失败的请求，例如

```js
fetch('https://no-such-host.invalid/x').catch(() => {})
```

几秒后展开「🔍 连接诊断」，应当能看到这一条（同时主进程控制台打出 `[Fireflux] 请求失败 … net::ERR_NAME_NOT_RESOLVED`）。

几个容易漏的点：

- 改窗口标题：`main/index.ts` 的 `title` 与 `index.html` 的 `<title>` **两处都要改**。
- 改 `MENU_BAND`：必须同步 `embed.html` 的 `controlsGutter`。
- 改 `ACCENTS` 的色名：同步 `Settings.svelte` 的默认高亮判断与 `app.css` 的默认 `--accent`。
- 改 `appId`：等于换安装身份，已装旧版本的机器会并排装出第二个应用。
- GitHub Actions 会自动决定 Release 版本：`master` 使用三段十进制进位版本（运行号 11 为 `0.2.1`），标签推送使用标签去掉 `v` 后的版本；每段必须是 `0~9`；本地 `version` 只作为源码和本地打包基线。

## 八、动态页的图片/网页加载不出来时怎么排查

动态页内嵌的 Memos 是**远端网页**，里面的图片裂开、连接被拒，客户端原本只能显示一片白（Chromium 只把 `net::ERR_*` 写到 stderr，既没有 URL 也不进界面）。现在这条链路会说话：

| 你会看到 | 意思 |
|---|---|
| 卡片右上角「加载中…」长期不变成「已加载」 | 主文档还没加载完；点「↻ 重新加载」再试 |
| 红色「加载失败」+ 黄色横幅（含 URL 与错误码） | 主文档没加载成功：服务没起来、地址写错、证书不受信任都会这样 |
| 「🔍 连接诊断」面板里的条目 | **某个具体请求**失败了，带时间、错误码、URL。图片裂开通常就在这里面 |
| 弹窗「证书不受信任」 | 某个站点（图片服务器也算）的证书验不过，选「继续访问」才会放行；同一个站点只问一次 |
| 主进程控制台的 `[Fireflux] 请求失败 <url> <net::ERR_xxx>` | 与面板同一批记录，方便直接复制日志 |

拿到 URL 之后按它判断：

- **站外图床/CDN 的地址**（微信、QQ、图床临时链接等）→ 外链已失效或在你网络里不通，客户端修不了；把图片重新上传到 Memos，或用「本地发布 → 插入本地图片」。
- **你自己的服务器、证书错误** → 用弹窗放行即可；根治办法是换成受信任的证书。
- **你自己的服务器、连接被重置**（`ERR_CONNECTION_CLOSED`）→ 多为反代/并发限制，需要在服务端看。

最快的对照实验：点动态页的「↗ 在浏览器打开」，用系统浏览器打开同一地址 —— 图也裂就是服务端或图源的问题，与 Fireflux 无关。

这套诊断本身的参数（都在 `src/main/services/webdiag.ts`）：

| 参数 | 现值 | 改了之后是什么样 |
|---|---|---|
| `MAX_KEEP` | 20 | 面板里最多保留多少条失败记录（按时间倒序，新的在前） |
| 「同一 URL + 同一错误」合并 | 合并计数并更新时间 | 轮询类接口反复失败时不会刷屏；想逐次都留一条就把 `record()` 里的合并判断去掉 |
| 面板刷新间隔 | 2000ms（展开时） | 诊断面板展开着的时候多久拉一次新记录 |
| 证书弹窗记忆 | 每个主机问一次（仅本次运行） | 同一个站点的多张图片只弹一次窗；想每次失败都问就清空 `askedHosts` 的判断 |
| 忽略的错误码 | `net::ERR_ABORTED` | 页面跳转、用户取消造成的正常中断不记；想让它们也出现就删掉那行过滤 |

改动落在三处：主进程 `src/main/services/webdiag.ts`（`webRequest.onErrorOccurred` 收集失败、`certificate-error` 询问是否放行、webview 的 `setWindowOpenHandler` 把外链交给系统浏览器）、IPC 通道 `webview:diagnostics`（`ipc.ts` → `preload` → `lib/api.d.ts`，数据结构 `NetworkFailure` 在 `src/shared/types.ts`）、界面 `src/renderer/src/pages/Dynamics.svelte`（加载状态、失败横幅、「🔍 连接诊断」面板）。
