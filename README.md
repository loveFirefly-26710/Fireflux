# Fireflux

**流萤博客的本地管理客户端 —— 改本地文件，一键推送上线的桌面座舱。**

Fireflux 是一个独立的 Windows 桌面应用（Electron + Svelte），用来管理**Firefly 主题的 Astro 博客**：
动态发布、文章与项目编辑、25 个配置文件全部图形化修改、git 提交与推送，外加一只常驻侧栏的流萤看板娘。

博客本身保持**纯静态**：客户端不改主题源码、不引入数据库，推送后由 GitHub Actions 自动构建上线。

源码基线版本为 **0.1.0**。安装包在 [Releases](../../releases) 里下载；推送 `master` 时，GitHub Actions 会把运行号按十进制进位生成三段版本号（例如运行号 11 为 `0.2.1`），每段都保持在 `0~9`；推送 `vX.Y.Z` 标签时使用标签版本，且标签也必须是三段单数字版本。

> 首次运行安装包会触发 Windows SmartScreen 提示（未做代码签名）：点「更多信息 → 仍要运行」即可。

## 功能

| 页面 | 能做什么 |
|---|---|
| 动态发布 | 远端模式内嵌 Memos 网页（按 `dynamicConfig` 自动选默认页签；带加载状态与「连接诊断」，图片裂开/连接被拒能直接看到是哪个 URL 失败）；本地模式表单发布、插图、从磁盘导入 md |
| 文章管理 | 列表 / 编辑 / 新建（中文标题自动转拼音 slug，与博客的 `new-post` 脚本一致）/ 删除 / 导入 md / 插入本地配图 |
| 项目展示 | 同上，对应 `src/content/projects` |
| Spec 页面 | about / friends / guestbook 等页面内容的编辑与导入 |
| 配置中心 | **25 个配置文件全部图形化**：下拉框、开关、列表增删排序、本地图片/视频/音乐/二维码导入（自动复制到约定目录并生成引用路径）；保存时只补丁改动的字段，注释与其余代码原样保留 |
| 发布上线 | 改动清单、暂存、提交、推送（推送前弹窗确认）、拉取最新、git diff 与提交历史 |
| 设置 | 绑定/更换博客项目文件夹、主题色、壁纸与不透明度、数据目录、看板娘开关与大小位置、硬件加速渲染 |

## 亮点

- **为软件渲染机器做的省电设计**：看板娘只在鼠标移动、指针停在它身上、点击摸头时逐帧渲染，其余时间渲染完最后一帧就完全停住（画面仍是流萤，只是不动），静止态 CPU 归零；背景预烘焙成一张 1:1 位图，拖拽时每帧只做一次 blit。细节与实测数字见 [开发笔记](docs/开发笔记.md)。
- **看板娘容器 = 模型 + 右侧按钮带子**：容器宽度跟着「模型大小」走，模型放大容器跟着放大、缩小跟着缩小，任何尺寸下都不裁切；消息框与调整提示条由父页面绘制在容器上沿之上（模型头顶）。
- **配置改不坏**：配置引擎基于 ts-morph，只替换被修改字段的字面量，中文注释、`as const`、跨文件引用一律不动；写盘前在内存里逐项复核，不一致就直接报错不写。
- **只动该动的文件**：所有读写在主进程按相对路径拼到博客项目根目录，并限制在 `src/content`、`src/config`、`public` 三个白名单目录内。
- **内嵌网页失败看得见**：Memos 里的图片裂开、接口断连、证书不受信任，都会带上 URL 与错误码出现在「连接诊断」里（含证书放行询问），不再是白屏猜谜。做法与坑见 [开发笔记](docs/开发笔记.md)。

## 快速开始

环境：Node 22+ 与 [pnpm](https://pnpm.io/)。

```bash
pnpm install
pnpm dev          # 开发模式启动
```

首次打开会要求**绑定博客项目文件夹**（包含 `src` 的那一层，也就是 Firefly 项目的根目录）。
绑定后所有读写都通过相对路径进行；文件夹挪了位置或换了电脑，在「设置」里重新绑定一次即可，其余功能照常。

打包成 Windows 安装包（NSIS，输出在 `release/`）：

```bash
pnpm dist
```

推送到 `master` 分支后，GitHub Actions 会自动构建并发布 Release（见 `.github/workflows/release.yml`）。master 发布版本按 Release 工作流运行号十进制进位生成：1~9 对应 `0.1.1`~`0.1.9`，10 对应 `0.2.0`，11 对应 `0.2.1`；推送 `vX.Y.Z` 标签时使用标签版本，且每段限制为 `0~9`。

## 数据存放在哪里

全部数据放在**应用自身旁边的 `data/` 目录**（便携式布局，整个目录可以直接拷走）：

- 开发模式：仓库目录下的 `data/`
- 安装版：`安装目录\data\`（装到不可写位置时自动回退到系统用户目录）
- 其中 `settings.json` 是外观与偏好，`wallpapers\` 是壁纸，`userData\` 是 Electron 缓存与网页会话，`pointer.json` 记录绑定的博客项目路径

这些数据不会写进博客项目，也不会被提交。设置页可以把数据目录换到别处（现有数据会自动复制过去）。

## 目录结构

```
src/main/        主进程：ipc / 设置 / 配置引擎 / git / 内容文件 / 资源导入
src/preload/     contextBridge 暴露给界面的 window.api
src/renderer/    Svelte 界面（页面、组件、表单 schema），看板娘资源在 public/live2d
src/shared/      主进程与渲染层共用的数据结构 types.ts、配置清单 registry.ts
scripts/         开发辅助脚本（性能归因台、硬件加速三态验证）
docs/            参数说明、开发笔记
```

技术栈：Electron 37 + electron-vite + Svelte 5 + TypeScript + ts-morph。

## 常见问题

- **Electron 下载慢或失败**：设置镜像后重装
  `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ pnpm install`
- **推送报错**：看「发布上线」页的日志原文，常见原因是网络或远端仓库权限。
- **配置改坏了**：改动前的版本都在博客项目的 git 历史里，`git checkout -- src/config/xxx.ts` 即可还原；客户端不另做备份。
- **配置里出现"只读代码块"**：个别字段由代码生成（如导航预设引用）或跨文件引用，暂不支持图形化修改，需在源文件里手动改。
- **看板娘不显示**：窗口高度小于 700px 时按设计隐藏；也可以在设置里关掉（关掉后拖拽更流畅）。
- **动态页里的图片裂开 / 内嵌网页打不开**：展开那张卡片底部左下角的「🔍 连接诊断」，里面会列出**具体哪个 URL 失败了、错误码是什么**（图片裂开通常就在其中），点「复制」可以直接贴出来。若某个站点证书不受信任会弹窗询问是否继续访问；先用「↗ 在浏览器打开」在系统浏览器里对照一下，能快速判断是图源/服务器的问题还是客户端的问题。
